# 监控管理 · 第一批（基础 + 告警规则 CRUD）部署与验证

> 2026-10-20 已按原型精简更新：7 张表；菜单 160–167；数据范围只按站点（普通用户也能看、能改全部规则）；通知群直接存 Lark chat_id；负责人只显示邮箱。

适用分支：`prod`　　目标库：`dashboard_db`　　服务：yata-prod-01（`fivetech`）

## 1. 本次改动

| 类型 | 文件 | 说明 |
| --- | --- | --- |
| SQL | `sql/alter_metric_card_monitor_postgresql.sql` | `dashboard_metric_card` 删除旧告警字段，新增监控属性与门槛条刻度（20 个可监控指标、7 个有刻度） |
| SQL | `sql/monitor_schema_postgresql.sql` | 新建 7 张 `monitor_*` 表，插入默认站点 SITE-IN 的设置行 |
| SQL | `sql/add_monitor_menu_postgresql.sql` | 菜单 160「监控管理」+ 按钮 161–167（含多语言）；顺带清掉旧版本加过的 168–172 |
| SQL | `sql/rollback_metric_card_monitor_postgresql.sql` | **只在回滚时用**：把旧字段加回来 |
| 后端 | `fivetech-system/.../monitor/**`、`mapper/monitor/*.xml` | MonitorScope、站点解析、规则校验、规则 Service / Mapper |
| 后端 | `fivetech-admin/.../controller/monitoring/MonitorRuleController.java` | `/monitor/rules*`、`/monitor/owners` |
| 后端 | `GlobalExceptionHandler` | 新增 400（data.fields）与 403 / 404 / 48xx 的处理 |
| 后端 | `MetricCardConfig`、`DashboardConfigMapper.xml` | 指标配置读新字段（**与 alter 脚本必须同时上线**） |
| 构建 | `fivetech-system/pom.xml` | 增加 junit-jupiter（test 范围） |
| 测试 | `fivetech-system/src/test/.../MonitorMapperScopeTest.java` | 监控 Mapper 的 select 必须带数据范围片段 |
| 联调 | `doc/monitor/monitor-rules.postman_collection.json`、`monitor_batch1_test_data.sql` | 72 个用例 + 测试数据 |

不新增环境变量（Lark 凭证 MONITOR_LARK_APP_ID / MONITOR_LARK_APP_SECRET 在第二批接入 LarkClient 时才需要），不改 Redis、UDS 配置。

> **上线顺序约束**：新 jar 启动时会读 `dashboard_metric_card` 的新字段，旧 jar 启动时会读被删掉的旧字段。
> 所以必须「先执行 SQL，紧接着发布 jar」。正在运行的旧进程只在启动时加载指标配置，执行 SQL 后到重启前不受影响。
> 如果发布失败需要退回旧 jar，**先执行回滚 SQL 再回滚 jar**（见第 7 节），否则旧 jar 也起不来。


### 4.2 执行（顺序不能换）

脚本内部自带 `BEGIN/COMMIT`，不要再加 `--single-transaction`。三个脚本都可以重复执行。

> 如果某个环境已经执行过旧版本的建表脚本（10 张表，含 monitor_lark_bot / monitor_site_admin / monitor_notify_group），且还没有业务数据：先执行 `monitor_schema_postgresql.sql` 末尾注释里的「清理旧版本」，再执行 ②。

```bash
psql -v ON_ERROR_STOP=1 -f alter_metric_card_monitor_postgresql.sql   # ① 指标监控属性（末尾自检：可监控 20、有刻度 7，不符会报错回滚）
psql -v ON_ERROR_STOP=1 -f monitor_schema_postgresql.sql              # ② 7 张表（末尾输出 monitor_tables = 7）
psql -v ON_ERROR_STOP=1 -f add_monitor_menu_postgresql.sql            # ③ 菜单（末尾输出 8 行）
```

## 7. 回滚

```bash
# 1) 先把旧字段加回来（旧 jar 启动需要）
psql -v ON_ERROR_STOP=1 -f /opt/fivetech/sql/monitor-batch1/rollback_metric_card_monitor_postgresql.sql
# 2) 再回滚 jar
sudo yata-deploy rollback
sudo yata-deploy status
```

- 新增的监控字段、`monitor_*` 表、菜单对旧 jar 无影响，可以保留，下次发布不用重建。
- 旧告警字段的值旧代码不使用，加回空字段即可启动。确需恢复旧值时，用 4.1 节的 csv 回填：

```sql
CREATE TEMP TABLE bak (metric_code varchar(64), alert_enabled boolean, alert_min numeric, alert_max numeric,
                       tolerance_pct numeric, tolerance_crit_multiple numeric, alert_level varchar(8));
\copy bak FROM '/opt/fivetech/backup/metric_card_alert_backup_<TS>.csv' CSV HEADER
UPDATE dashboard_metric_card c SET alert_enabled = b.alert_enabled, alert_min = b.alert_min, alert_max = b.alert_max,
       tolerance_pct = b.tolerance_pct, tolerance_crit_multiple = b.tolerance_crit_multiple, alert_level = b.alert_level
FROM bak b WHERE b.metric_code = c.metric_code;
```

- 4.1 节的 `.dump` 是整表快照，只在需要人工核对旧配置时用 `pg_restore -f - <dump>` 导出成 SQL 查看，不要直接覆盖恢复。
