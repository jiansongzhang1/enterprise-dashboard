# RuoYi-Vue 当前项目数据库梳理

## 1. 项目概览

当前仓库是一个典型的前后端分离后台管理系统，后端按模块拆分为：

- `ruoyi-admin`：Web 接口入口、系统与监控控制器
- `ruoyi-common`：公共实体、工具类、权限与通用基础能力
- `ruoyi-framework`：安全框架、数据源、拦截器、登录与权限支撑
- `ruoyi-system`：系统管理核心业务
- `ruoyi-quartz`：定时任务调度
- `ruoyi-generator`：代码生成器

## 2. 数据库脚本现状

仓库内当前只有两个 SQL 初始化脚本：

- `sql/ry_20260417.sql`：只定义了 `sys_config`
- `sql/quartz.sql`：定义 Quartz 调度所需的 `QRTZ_*` 系列表

这意味着：

- `sys_config` 是仓库里唯一显式给出建表语句的业务表
- 其余系统表虽然没有全部出现在 `sql/ry_20260417.sql` 中，但在代码的 `Mapper` 和实体类里都有明确引用，属于当前项目的实际业务模型
- `QRTZ_*` 表是 Quartz 的调度基础表，不属于业务表

## 3. 核心表与功能对应

### 3.1 系统管理类表

| 表名 | 功能 | 说明 |
|---|---|---|
| `sys_user` | 用户管理 | 系统用户主表，保存账号、部门、状态、头像、最后登录信息等 |
| `sys_role` | 角色管理 | 角色主表，定义角色名称、权限字符、数据权限范围、状态等 |
| `sys_dept` | 部门管理 | 组织机构表，支持树形结构、父子部门、祖级路径 |
| `sys_menu` | 菜单管理 | 菜单与按钮权限表，维护路由、组件、权限标识、图标等 |
| `sys_post` | 岗位管理 | 岗位主表，维护岗位编码、名称、排序、状态 |
| `sys_dict_type` | 字典类型管理 | 字典分类表，维护字典大类 |
| `sys_dict_data` | 字典数据管理 | 字典明细表，维护具体字典值、标签、样式、默认项 |
| `sys_config` | 参数配置管理 | 系统参数配置表，当前脚本中唯一显式建表的业务表 |

### 3.2 关联关系表

| 表名 | 功能 | 说明 |
|---|---|---|
| `sys_user_role` | 用户-角色关联 | 一个用户可以拥有多个角色 |
| `sys_user_post` | 用户-岗位关联 | 一个用户可以绑定多个岗位 |
| `sys_role_menu` | 角色-菜单关联 | 角色授予哪些菜单/按钮权限 |
| `sys_role_dept` | 角色-部门关联 | 自定义数据权限时，角色可访问的部门范围 |

### 3.3 日志与公告表

| 表名 | 功能 | 说明 |
|---|---|---|
| `sys_oper_log` | 操作日志 | 记录接口调用、业务类型、请求参数、返回结果、耗时、异常等 |
| `sys_logininfor` | 登录日志 | 记录登录成功/失败、IP、地点、浏览器、操作系统、时间等 |
| `sys_notice` | 通知公告 | 系统公告/通知发布、编辑、启停用 |
| `sys_notice_read` | 公告已读记录 | 记录某个用户是否已读某条公告，以及阅读时间 |

### 3.4 定时任务表

| 表名 | 功能 | 说明 |
|---|---|---|
| `sys_job` | 定时任务配置 | 业务层任务定义，保存任务名、分组、调用目标、Cron、并发策略、状态 |
| `sys_job_log` | 定时任务日志 | 记录任务执行结果、异常信息、开始结束时间 |

### 3.5 代码生成器表

| 表名 | 功能 | 说明 |
|---|---|---|
| `gen_table` | 业务表元数据 | 代码生成器保存的表配置，包括表名、实体名、模板类型、包名、模块名、功能名等 |
| `gen_table_column` | 业务字段元数据 | 代码生成器保存的字段配置，包括字段名、类型、是否主键、是否查询、表单控件类型等 |

## 4. Quartz 调度表

`sql/quartz.sql` 里的 `QRTZ_*` 是 Quartz 官方调度表，用于任务调度引擎本身，不承载业务数据。

| 表名 | 功能 | 说明 |
|---|---|---|
| `QRTZ_JOB_DETAILS` | 任务详情 | 保存 jobDetail 的完整定义 |
| `QRTZ_TRIGGERS` | 触发器主表 | 保存触发器的通用信息与状态 |
| `QRTZ_SIMPLE_TRIGGERS` | 简单触发器 | 保存重复次数、间隔等简单调度策略 |
| `QRTZ_CRON_TRIGGERS` | Cron 触发器 | 保存 Cron 表达式和时区 |
| `QRTZ_BLOB_TRIGGERS` | Blob 触发器 | 保存自定义 Trigger 的二进制内容 |
| `QRTZ_CALENDARS` | 日历表 | 保存 Quartz 日历对象，用于排除特定时间段 |
| `QRTZ_PAUSED_TRIGGER_GRPS` | 暂停触发器组 | 保存被暂停的触发器组 |
| `QRTZ_FIRED_TRIGGERS` | 已触发记录 | 保存触发器已触发状态及关联执行信息 |
| `QRTZ_SCHEDULER_STATE` | 调度器状态 | 集群环境下保存调度器实例心跳状态 |
| `QRTZ_LOCKS` | 悲观锁表 | Quartz 集群同步用锁信息 |
| `QRTZ_SIMPROP_TRIGGERS` | 同步触发表 | Quartz 集群同步机制相关的行锁/属性表 |

## 5. 不落库但和功能强相关的对象

下面这些类名里虽然带有“表”语义，但当前代码里更偏运行态对象，不对应独立业务表：

| 对象 | 说明 |
|---|---|
| `SysUserOnline` | 在线用户会话信息，主要来自 Token/Redis/内存态，用于在线用户监控 |
| `SysCache` | 缓存监控展示对象，表示缓存名称、Key、Value、备注 |

## 6. 按功能模块快速索引

- 用户、部门、岗位、角色、菜单、字典、参数：`sys_user`、`sys_dept`、`sys_post`、`sys_role`、`sys_menu`、`sys_dict_type`、`sys_dict_data`、`sys_config`
- 权限关系：`sys_user_role`、`sys_user_post`、`sys_role_menu`、`sys_role_dept`
- 公告与阅读状态：`sys_notice`、`sys_notice_read`
- 审计日志：`sys_oper_log`、`sys_logininfor`
- 定时任务：`sys_job`、`sys_job_log`、`QRTZ_*`
- 代码生成：`gen_table`、`gen_table_column`

## 7. 结论

从当前仓库代码看，项目数据库可以分成三层：

1. **系统业务表**：用户、角色、部门、菜单、字典、公告、参数
2. **支撑关系表与日志表**：用户角色、角色菜单、登录日志、操作日志、任务日志
3. **基础设施表**：Quartz 调度表、代码生成器元数据表
