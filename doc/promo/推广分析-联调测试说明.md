# 推广分析 · 后端联调测试说明

2026-11-05 · 对应代码：`com.fivetech.promo.analysis`（含 `market` 子包）、`PromoAnalysisController`、`OverviewController`（scene = PROMO）

用例集：`doc/promo/promo_analysis.postman_collection.json`（第 1–8 组只读，2.3 的前置操作会写库；第 9 组个人视图只写当前登录用户自己的记录，首尾各重置一次）。
字段口径依据：Daniel《推广分析：页面指标与数据集字段对照》（2026-11-05）与 UDS market Postman 联调包。

## 1. 准备

1. 数据库：执行 `sql/release_next_postgresql.sql` ⑤（可歸因列、推广指标与页面、菜单 `dashboard:promo:view`），再启动新 JAR。
2. 配置中心：
   - `PROMO_CHANNELS` 改为带 ID 的格式（示例见新增页）；
   - 新增 `PROMO_TERMINALS`，终端 code 用 `web` / `android` / `ios`（对应 UDS 的 Web / Android / iOS；未識別系统自动加）。
3. UDS：后端能连上 UDS（`UDS_BASE_URL`，本地用 SSM 隧道）。市场数据集的配置在 `application.yml` 的 `promo.market`：
   - `enabled`：关掉后全部按「数据待接入」返回；
   - `merchant-code`（`PROMO_MARKET_MERCHANT_CODE`）：UDS 要求按 merchant_code 过滤时填，否则留空。
4. 账号权限：`dashboard:promo:view`、`dashboard:record:member`、`promo:budget:view`。
   个人视图（第 9 组）另需执行 `sql/release_next_postgresql.sql` ⑦（4 张表 + 推广分析 3 个配置位的初始数据）；有 `dashboard:promo:view` 即可读写自己的视图。
5. Postman 变量：`baseUrl`、登录信息或 `token`、`siteCode`（SITE-IN）、`tzOffsetMin`（印度 330）、`fissionUserId`（一个有下级的代理）。
6. 2.3 按终端归因：先在「系统管理 › 指标管理」把 `promoReg`（註冊人數）的「可歸因」打开。

## 2. 取数对照

| 页面指标 | 接口编码 | UDS 字段 | 取法 |
| --- | --- | --- | --- |
| 註冊人數 | reg | 宽表 `reg`；选终端用 `web_reg` / `android_reg` / `ios_reg` / `unknown_reg` | 求和 |
| 首存人數 / 首存金額 | ftd / ftdAmt | 宽表 `ftd_players` / `ftd_amount`（终端同上加前缀） | 求和 |
| 首存轉化率 | ftdR | `ftd_players` ÷ `reg` | 后端算，百分数 2 位 |
| 複存人數 | rd | 精确 `redeposit_users` | 按日分组后相加（多天按日累加） |
| 複存金額 / 複存率 | rdAmt / rdR | 宽表 `redeposit_amount`；Σ`redeposit_users` ÷ `ftd_players` | |
| 存款人數 / 存款率 | depU / depR | 精确 `deposit_users`（按日累加）；÷ `reg` | |
| 存款總額 / 淨充值 | dep / net | 精确 `deposit_amount` | 淨充值 = 存款总额 |
| ARPPU | arppu | `deposit_amount` ÷ Σ`deposit_users` | |
| 投注人數 / 投注總額 | betU / bet | 精确 `bet_users`（按日累加）/ `bet_amount` | |
| 激活 | act | 宽表 `android_first_open` | 没有终端拆分，只在全部与 Android 有值 |
| ROAS D7 / D30 | roas7 / roas30 | 由 UDS 计算（字段待 UDS 提供） | 后端不计算，取到后原样返回；目前 NO_SOURCE |
| 流失 N 人 | funnel `lost` | 会员快照：`register_time` 在区间内且 `is_ftd = 0`，按 `terminal` 过滤 | `record_count` |
| 裂變層級（进入某用户） | fission | 会员快照 `agent_login` = 该用户帐号列出直属下级；小时数据集按 `agent_login` 汇总 `reg`、`ftd_players`、`deposit_users`、`deposit_amount`、`bet_amount` | 上级为会员当前上级 |

后端每次取数发两条请求（宽表、精确人数不能混查，用 `/query/batch` 一次发出），时间窗 `to` 为最后一个包含的整点。

## 4. 对数方法

用 UDS market Postman 包同一时间窗、同一站点对比（后端的时间是左闭右开，UDS 的 `to` 是最后一个整点）：

| 后端 | UDS 联调包 |
| --- | --- |
| 2.1 注册、首存、首存金额合计 | 06 区间总览（`reg`、`ftd_players`、`ftd_amount`） |
| 2.1 序列（按日） | 07 逐日注册首存趋势 |
| 2.2 Web 注册 | 08 注册终端拆分宽表 `web_reg` |

## 5. 已知限制

- 市场数据只覆盖 2026-07-26 起注册的有效会员，更早的日期为 null（无数据）而不是 0；生产入口目前仍是 ads-test 测试数据。
- IVI 九站整集缺口：数值为 null，概览 notices 有 PROMO_SITE_NO_DATA。
- 推广商 / 推广渠道、直推 / 裂变、消耗与预算、成本类、留存与回收、提款、有效投注、GGR、UV、下载点击、注册转化率仍待数据平台补源或产品确认口径（见对照文档「待补源与待决事项」）。
