# 推广分析 · 预算与消耗导入（FY-56）· 后端说明

需求：[FY-56](https://itops8.atlassian.net/browse/FY-56)，需求文档 1452114068（第 22 版：6 列模板，规则编号 R、F1–F7、V1–V17 与文档一致）。

## 范围

- 上传的文件在内存里解析、校验，不保存文件、不建表、不落库。
- 数据存放在数据平台（依据《市场预算、消耗：后端端到端联调手册》2026-11-06），预算、消耗各一对接口：
  - **写**：采集平台统一提交接口 `POST /v1/imports/market-cost:submit`、`market-budget:submit`（Bearer + `Idempotency-Key`），同步返回（`CollectBudgetSpendWriter`）；
  - **读**：UDS `POST /v1/query`，数据集 `import_yata_promo_cost` / `import_yata_promo_budget`，走现有 UDS 客户端（地址、证书、`X-Uds-*` 身份头）；一次查询、`offset=0`、limit 10000，不偏移翻页，`complete=false` 报错不补零。
- 渠道字典（模板预填、V7–V13）在后台「系统管理 › 配置中心」维护：配置编码 `PROMO_CHANNELS`，按站点各一条（站点为空 = 全站通用，站点自己的优先）。表与菜单见 `sql/release_next_postgresql.sql` ④。

### 渠道字典 PROMO_CHANNELS（2026-11-05 起带 ID）

```json
[
  { "id": 1001, "name": "hada", "channels": [
    { "id": 2001, "name": "DSP-hada",  "media": "DSP",  "status": "ACTIVE", "entryType": "LANDING" },
    { "id": 2002, "name": "meta-hada", "media": "meta", "status": "ACTIVE", "entryType": "LANDING" }
  ] },
  { "id": 1002, "name": "jason", "channels": [
    { "id": 2003, "name": "TG-jason", "media": "TG", "status": "ACTIVE", "entryType": "MAIN" }
  ] }
]
```

- `id`：字符串或数字，按值比较（`1001`、`1001.0`、`"1001"` 相同）；推广商 ID、推广渠道 ID（整份字典内）不能重复；名称也不能重复（不区分大小写）。
- `media`：投放媒體（投放日报用），不填显示「未分類」；`status`：`ACTIVE` / `DISABLED`（默认 ACTIVE，停用的照常列出）；`entryType`：`LANDING` / `MAIN`（默认 LANDING，决定注册转化率的分母）。
- **旧格式（只有名称、`channels` 是字符串数组）不再接受**：配置中心保存时报错；库里还是旧格式时按空字典处理并记警告。上线后请在配置中心按示例改一次。
- 推广分析的筛选、投放日报、用户明细筛选也读这份字典；`code` 即这里的 `id`。

## 校验要点

- 文件级 F1 → F7，遇到第一个即整份不导入；F7 只看通过日期校验（V1–V6）的行。
- 表头比较忽略空格；第 6 列是另一种类型 → F3；旧的 4 列模板 → F4「第 1 行應為「日期｜推廣商 ID｜推廣商名稱｜推廣渠道 ID｜推廣渠道名稱｜消耗」，請下載新模板。」
- 行级每行按以下顺序检查，遇到第一个即停：
  - 日期 V1–V6；
  - 推广商 V7 ID 为空 / V8 找不到这个推广商 ID / V9 名称与 ID 不一致（名称为空也算；提示「（ID {x} 為「{系統名稱}」）」）；
  - 推广渠道 V10 ID 为空 / V11 找不到这个推广渠道 ID / V12 名称与 ID 不一致 / V13 推广渠道不属于这个推广商；
  - 金额为空（不导入、不算失败）→ V14 不是数字 / V15 小于 0 / V16 超过 2 位小数。
- V17 对有效行与金额为空的行按「日期 × 推广渠道 ID」统一判重，重复的行全部失败。
- 名称比较：去首尾空格、连续空格合一、不区分大小写；以 ID 为准，名称只核对。
- 行号 = 文件实际行号（空白行占号）；`total` 不计空白行、计入金额为空的行。
- .xlsx 只读第一个工作表；日期、数值类型的单元格按值识别（ID 写成数值单元格也可以），文本单元格按格式校验。.csv 按 UTF-8（可带 BOM），不是合法 UTF-8 时按 GB18030。
- 「今天」按站点时区；数据起始日取 `dashboard.launch-date`；预算最远今天＋90 天。

## 写入流程

平台「上传成功会替换该类型、该站点、目标日期的全部数据」。FY-56 的规则是同一「日期 × 推广渠道」覆盖、金额为空的行保留原值，所以：

1. 先从 UDS 读出这些日期已发布的行（读失败就不写，避免整日替换丢掉其他渠道的数据）；
2. 用本次有效行按「日期 × 推广渠道 ID」覆盖，其余（含渠道字典外的渠道）原样带上，按日期、推广商 ID、推广渠道 ID 排序；超过 5000 行或 2 MiB 提示缩短日期范围分次导入（不拆同一天）；
3. 生成本次上传的 `Idempotency-Key`，`POST {"rows": [...]}`：
   - 200 `SUCCEEDED`：写入成功；
   - 202 `PROCESSING`、429、503、5xx、超时断连：按 `Retry-After`（没有时 2、4、8… 秒，封顶 30 秒，加抖动）用同一 URL、同一 key、同一请求体重发，最多 60 秒；还没结果返回 `PROCESSING`，页面「重新查詢結果」再原样发；
   - 409 `overwrite_confirmation_required`（及 `confirmation_expired` / `confirmation_changed`）：没有导入，页面列出将整日替换的日期和提交行数，用户点「確認覆蓋」后同一 key、同一 rows 前面加上 `confirmation_id` 再发；不自动同意；
   - 400 `row_validation_failed`（`errors[].row` 从 1 起，对回文件行号；合并带上的原有数据标「平台原有數據」）、409 `stale_base` / `idempotency_conflict`、422、401、403、404、413、415：失败，不重试。
4. 金额以十进制字符串提交（最多 4 位小数，不用 JSON 数字），ID 原样字符串（保留前导零），名称可为 null。

不做撤销、清空：导错了重新导入正确的值，某格要变成 0 就填 0。

## 配置（`application.yml` 的 `promo.budget-import`）

| 配置 | 环境变量 | 说明 |
| --- | --- | --- |
| `enabled` | `PROMO_BUDGET_IMPORT_ENABLED`（默认 false） | 写入开关；关闭时导入只校验 |
| `read-enabled` | `PROMO_BUDGET_READ_ENABLED`（默认 true） | 读取开关；关闭时表格无数据、预算模板不预填，写入也不可用 |
| `collect-base-url` | `COLLECT_BASE_URL` | 采集接口地址，不带 `/v1`：内网 `http://10.32.16.5:8090`，本机转发 `http://127.0.0.1:18090` |
| `token` | `COLLECT_TOKEN` | 采集 Bearer token，只放环境变量；须与 UDS 身份指向同一站点 |
| `site-tokens` | — | 多个站点各有 token 时按站点编码配置（值引用环境变量） |
| `request-timeout-seconds` / `submit-wait-seconds` | — | 20 / 60 秒 |
| `pending-ttl-minutes` | — | 待确认、处理中的提交保留 30 分钟（平台确认编号默认 10 分钟有效） |
| `max-rows` / `max-bytes` | — | 5000 行 / 2 MiB |

读取用现有 UDS 客户端：`UDS_BASE_URL=https://10.32.16.83:8443`、证书 `UDS_TLS_*`，身份 `UDS_PRINCIPAL=cmp1-backend`、`UDS_TENANT=site:SITE-IN`、`UDS_ROLES=dashboard_ops`（SITE-IN 当前分配的值）。

## 联调注意

- 手册里的地址是正式服务，写入会改变真实数据；用与接口提供方约定、可整日替换的测试站点和日期。没有授权时保持 `enabled=false`，只验证读取（Postman 8.3、8.4）。
- 结束后如需删除合成数据，把站点、日期、类型和成功回执（`importId`）交给接口提供方清理；空 rows 不能清空。
