## 4. 推广分析（FY-46）关键结论

### 4.1 数据来源
- 市场数据集 `dashboard_market_hour_v1`：**宽表**（维度 `uds_hh` 等，终端用 `web_/android_/ios_/unknown_` 前缀字段）与**精确**（按 `terminal` 分组）不能同一请求混用。
- 会员快照 `dashboard_market_member_snapshot_v1`（2026-07-26 起注册）；用户快照 `dashboard_player_snapshot_v3`。
- 消耗 / 预算：UDS `import_yata_promo_cost / budget`（运营导入，按 `biz_date × 推广商 × 推广渠道`），读取开关 `promo.budget-import.read-enabled`。
- 生产 UDS 当前读 `ads-test`，真实市场数据止于 2026-09-30。

### 4.2 指标现状（代码）
- `MarketValues.AVAILABLE`：reg、ftd、ftdR、ftdAmt、rdAmt、rd、depU、depR、dep、net（暂定 = 存款总额）、arppu、betU、bet、act（宽表 `android_first_open`，只在全部 / Android 有值）。
- `MarketValues.FIELDS`：页面指标 → UDS 字段对照；`MarketGateway.cube(from,to,g,codes,byTerminal)` **只取请求指标用到的字段**，只要一边时只发一条 `/v1/query`，两边都要才 batch；带终端前缀字段只在选了终端 / 按终端归因 / 行维度有终端时取。改 `value()` 必须同步改 `FIELDS`（有单测核对）。
- `CALIBER_DIFF`（口径待确认，不展示）：lpPV、lpUV、dl、regR、uvCost。
- **複存率 rdR：讨论结果由上游直接给，后端不计算**（`MarketValues.UPSTREAM`），字段提供前 NO_SOURCE「由數據平台直接提供（不由後端計算），待接入」。待 UDS 给：字段名、宽表/精确、百分数还是小数、多天怎么汇总。
- 激活、复存率曾按映射文档改为「需确认」，**被回退**；激活目前仍展示 `android_first_open`（等用户决定）。
- 消耗 / 预算：`PromoSpend` 已接入概览卡（可按推广商/渠道筛选；本期含今天时消耗两期都去掉今天）、渠道表现（合计 / 日期 / 推广商 / 推广渠道行；终端、推广关系行 NA）、投放日报（列出有记录的渠道并填消耗）。没录入为 null 不是 0；读取失败标「暫時無法取得」。
- 成本类 CPA / 首存成本 / D0 ROI / UV 成本：`PromoCost` 按**有效格子**（已录入消耗且 > 0 的「日 × 推广渠道」）计算已写好；行为数据按推广渠道拆之前 `ChannelBehavior.NONE` 返回 null → NO_SOURCE「按推廣渠道的註冊 / 首存 / 淨充值待數據平台提供」。U1 到位后只需实现 `ChannelBehavior`。
- 渠道表现按推广商 / 推广渠道拆的行，注册等行为指标为空（「推廣渠道映射待接入」）：宽表没有推广渠道维度。**备选方案**（待确认）：在 `PROMO_CHANNELS` 字典里给渠道配推荐码，用宽表 `referral_code` 换算到渠道。

### 4.3 变化归因 `attribution`
- 请求带 `attribution.dimension`（agent / channel / terminal）时**每张卡都返回**：`supported`、`reasonCode`（NOT_CONFIGURED / TERMINAL_SELECTED / NOT_BY_TERMINAL / PENDING_SOURCE）、`reason`（展示文字）、`total`、`rows`。
- 没开「可歸因」→ NOT_CONFIGURED，文案「{指标名}是比率類指標…」（**计数 / 金额类也显示这句，不合适，待产品 P10 定**）。
- 「可歸因」开关：`dashboard_metric_card.attributable`，指标管理可改，保存立即生效；测试环境只开了淨充值、復存人數。
- `/system/metrics/{code}/update`（指标管理编辑保存）；管理后台前端已加「可歸因」开关（列表列 + 编辑弹窗，登记时不显示），e2e `tests/system-metric.spec.js`。
- 概览不传 `metrics` 只返回 `is_default` 的 10 张卡；运营总览的 `ftd` ≠ 推广分析的 `promoFtd`。

### 4.4 概览请求链路（例：metrics=["ftd"]、DAY、PREV_PERIOD、归因 agent）
- `PREV_PERIOD` 时 `compareFrom/To` 被忽略（只有 CUSTOM 才用）。
- 现在：本期、对比期各 1 次 `/v1/query`，只查宽表 `ftd_players`；归因 agent 不查 UDS（PENDING_SOURCE / NOT_CONFIGURED）。

### 4.5 用户明细（`POST /dashboard/records/member`）
- 新增 3 列：`registerTerminal`（+Label，用户快照 `terminal`）、`agentAccount`（`agent_login`）、`lastLoginTime`（从市场会员快照按本页用户 ID 补，`page-only-columns`，不进 UDS 导出）。
  - 用户说 `terminal`、`agent_login` 在用户快照 v3 里也有（与映射文档说法不同，待 UDS 确认 U8）。
- `terminals` 筛选：yml `details.member.fields.registerTerminal: terminal` + `value-maps`（web→Web、android→Android、ios→iOS、unidentified→Unknown）。
- `lost: true` = 只看流失用户（注册后至今未首存）；为空 / false 维持原逻辑；UDS 字段先留空 `filter-fields.lost: ""`，带 `lost=true` 返回 5001「暫時不能按它篩選」。
- `promotionDrill` 后端**忽略**（已告诉前端用明细现有参数拼下钻）。
- 推广商 / 推广渠道筛选：仍未映射（D2：用户快照 `channel` 能否对应推广渠道 ID）。

## 8. API Key（系统对接，2026-11-10）
- 请求头 `X-Api-Key: ftk_…`；只有 `security.api-key.paths`（目前只有 `/notification/lark/send`）认 Key，其他接口带了也不算登录。
- 每个 Key 绑定一个后台账号（按其权限放行、日志记其名下）；可限接口、来源 IP（用 `ClientIpResolver`，防伪造 XFF）、到期时间；作废立即失效。
- 库里只存 SHA-256 + 前 12 位；明文只在新建时返回一次（`@Log(isSaveResponseData=false)`）；校验失败统一 401「API Key 無效、已過期或不能訪問該接口」，原因只写日志。
- 代码：`com.fivetech.apikey`（`ApiKey`、`ApiKeyMapper`+XML、`ApiKeyService`），`framework/security/filter/ApiKeyAuthenticationFilter`（在 JWT 之前），`SysApiKeyController`（`/system/api-keys`：GET 列表、POST 新建、POST `/{keyId}/revoke`，**只认登录 token**），测试 `ApiKeyServiceTest`。
- 新建 body：`{keyName, userId(数字), allowedIps?, expireTime?, allowedPaths?, remark?}`；Postman 要用 raw JSON。建议绑定只有「Lark发送」权限的专用账号（测试可用 admin=1，正式换专用账号并作废测试 Key）。
- 开了管理接口 IP 白名单时，调用方 IP 也要在白名单里。
